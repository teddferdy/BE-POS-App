# Migration baseline manifest for chain validation.
#
# PROVENANCE BOUNDARY (read this before editing):
#
# The repository is intentionally snapshot-first: scripts/dev-schema.sql is
# the documented schema baseline, and db/migrations/ holds incremental
# changes on top of it. The full chain CANNOT bootstrap an empty database
# (core tables such as "user", "product", "order", "location" and "category"
# have no createTable migration) and it CANNOT run unmodified against a
# snapshot-loaded database either (early unguarded migrations assume their
# own historical states — e.g. 20260601000001 fails on snapshot state).
#
# This file therefore lists exactly the migrations whose effects the
# baseline snapshot already embodies. The chain validator
# (scripts/validate-migration-chain.js) stamps THESE names into
# SequelizeMeta on a snapshot-loaded ephemeral database and then executes
# every remaining migration file for real through `sequelize-cli db:migrate`.
#
# RULES:
# - A migration belongs here only once its effects are present in
#   scripts/dev-schema.sql (verify by catalog inspection, not by date).
# - When dev-schema.sql is refreshed to absorb pending migrations, add
#   those migration names here in the same change (reviewed together).
# - NEVER add a migration here to silence a failing validation run without
#   proving its effects exist in the snapshot.
# - NEVER remove a name except to fix a proven manifest error.
#
